## Findings fixed

1. **Medium, availability — cancellation leaked acknowledged stream reservations.** `asyncio.CancelledError` derives from BaseException, so the admission cleanup's `except Exception` did not release a global slot when cancellation interrupted acquisition of the principal slot. Cancellation of the initial evidence insert also bypassed the route's cleanup before its guarded stream existed. Repeated cancelled requests could temporarily exhaust stream slots until the 120-second expiry. Admission now cleans up on BaseException and re-raises; the initial-write path explicitly releases reservations and records a sanitized cancellation outcome before propagating cancellation. Tests reproduce cancellation at both stages and assert no acknowledged slots remain. This does not imply arbitrary remote privilege escalation: an eligible authenticated caller was still required to reach stream admission.
2. **Low, authority validation — empty userinfo was accepted.** Truthiness checks treated empty usernames/passwords like absent userinfo. `Host: @allowed-host` could therefore pass the exact-host boundary for an already authenticated request. The same validation pattern existed in CORS-origin policy and provider endpoint configuration. Explicit `is not None` checks now reject any userinfo, including empty values. Tests cover malformed Host authorities, origin policy and provider URLs. This was not an authentication or scope bypass.

The regressions failed before the corresponding corrections. Provider streaming, request budgets, exception redaction, TLS verification and existing successful authorized API/SSE behavior remain intact.

## Security assessment

- **Authentication/authorization:** expiry-checked, high-entropy bearer tokens are compared against private hash-only policy entries. Scope mapping is server-side and exact. Monitor credentials cannot run audits; role/scope/body/query spoofing cannot elevate privileges. No wildcard admin or publication scope exists. Policy loading fails closed on unsafe files or missing configuration. Static tokens remain replayable if stolen; configuration changes/revocation require coordinated worker restart, and admitted streams remain bounded rather than being reauthorized on every delta.
- **Rate and stream limits:** shared MongoDB atomic counters and token-owned expiring leases protect across workers/restarts. Rotation retains a principal's budget. Global/peer admission budgets include invalid authentication. Actual TCP peer identity is used; forwarded-IP and User-Agent changes do not create new buckets. Fixed-window boundary bursts, synchronized clocks, consistent policy/HMAC configuration and reviewed database failover behavior remain documented constraints. Unknown-result database writes, cleanup outages or repeated cancellation during cleanup can still leave a fail-closed lease until its bounded expiry; this is preferable to admitting an untracked extra stream.
- **Proxy/network:** explicit host/CIDR/origin lists, no `/0` trust, restricted preflights, actual-peer proxy trust and exact HTTPS attestation. The supplied launch commands disable Uvicorn proxy-header rewriting. Operators must maintain that setting and configure the TLS ingress to overwrite forwarded-proto headers. The legacy Node proxy is not a trusted TLS attester. No public firewall rule, ingress or host was modified.
- **Secrets/privacy:** private regular single-link files, UID/mode checks, bounded reads, secret-value redaction from settings repr, no raw client token in server policy/image/logs. Bootstrap generation never prints or overwrites credentials. Protect parent directories and the host UID; these checks cannot defend against a compromised host or malicious same-UID process. New cancellation logs contain only generated request IDs, timestamps, a fixed outcome and keyed principal reference.
- **Audit/error boundaries:** requests and stream outcomes use structured metadata, fixed route aliases and HMAC references; no headers, body, raw IP, paths/queries, provider exceptions or coordinate values are logged. Validation/unhandled request failures are sanitized. Completion is recorded after persistence, not as publication approval. Stdout needs an operator-provided durable private collector, quotas, retention and alerting; application rate limiting alone cannot prevent network floods or log-volume exhaustion.
- **Evidence/publication:** only backend cancellation/authority checks, their tests and this review changed. Raw source provenance, offline snapshot retention, coordinate handling and permission migration remain unchanged. TTL deletion applies only to ephemeral security counters/leases, never financial messages or source evidence. No new privilege allows intelligence publication or bypasses human approval.
